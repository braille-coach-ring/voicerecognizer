# 話者独立比較の固定評価手順

## 実装と実行条件

- 作業ブランチ: train/speaker-independent-female、開始 HEAD: 41cbc61be6d06dd31c91556fbecea0e0694f11bb。
- Train 6,124件、Val 1,058件、Test 620件を維持。CSV の指定後にランダム再分割しない。
- ファイル、話者、音声 SHA-256 の重複を検査。欠損や未評価の行があれば停止する。
- テスト由来の混同行列を使うサンプラーは停止。クラス重みと通常のクラス均衡サンプラーは Train のラベルのみから計算する。
- 選択指標: 固定 Val の同音統合後 Macro-F1。じ/ぢ、ず/づ、お/をを統合する。
- Macro-F1 は正解ラベルに実際の支持数があるクラスの平均。全ラベルを分母にする inventory_macro_f1 も併記する。
- 正規化前後の Accuracy、Macro-F1、Weighted-F1、各話者・生声/TTS別の値、話者平均 Accuracy、欠落ラベルを JSON に保存する。元の予測ラベルを保持する。
- 各実験の実行時ソース、データ、初期モデルの SHA-256 と学習設定を保存する。

## 比較する条件

1. fresh: facebook/wav2vec2-base の事前学習重みから新規ファインチューニング。
2. warm_start: 保存済みの過去最良モデルから継続学習。
3. phoneme_multi: 同じ過去最良モデルに PR #53 の既存子音・母音ヘッドを追加。文字損失 + 0.5×子音損失 + 0.5×母音損失。

最大15 epoch、batch size 8、学習率3e-5、Transformer先頭4層を固定、patience 5、seed 42、DataLoader workers 0。同一の既存前処理・データ拡張を利用する。各 run で Val が最良だったモデルを評価する。過去の共有モデルとの勝ち負けで保存を抑制しない。

## 解釈上の制限

既存チェックポイントの学習データ由来は未確認。warm_start と phoneme_multi は探索的な比較であり、完全に未知の話者への評価を保証しない。Test は過去に繰り返し調べた固定ベンチマークで、新しい盲検評価ではない。

Val に女性の生声がない。女性への汎化性能を判断するには、訓練とは別の女性生声を開発・最終評価用に確保する必要がある。TTS の話速・ピッチを変えるだけでは新しい実話者の評価を代替できない。

まず生声だけの比較を行う。TTS の追加効果は同じ手順で後続の比較として確認する。共有モデルへのアップロードは自動で行わない。

## 検証

追加の固定分割・正規化・話者継承・補助損失・チェックポイント互換テストと既存データ前処理テスト: 8件成功。先行の関連テストも31件成功（既存のHTMLレビュー表示テスト1件を除外）。そのHTMLテストの失敗は変更前 HEAD の評価コードでも再現した。

変更・追加したファイルに Ruff と型チェックの新規エラーなし。リポジトリ全体の型チェックでは、開始時から存在する未追跡 analyze_confusion.py に4件残る。

## 実行

隔離 worktree で PYTHONPATH を src とリポジトリルートへ、VOICERECOGNIZER_CACHE_DIR を worktree 内へ設定する。

```powershell
& 'C:/Users/yamadarikuto/Mycode/voicerecognizer/.venv/Scripts/python.exe' -u -m script.run_speaker_independent_colab --initial-model 'C:/Users/yamadarikuto/.cache/voicerecognizer/weights/wav2vec2_best'
```

実行先は専用 Colab T4 セッション vr-si-20261003-a100ad。大きなファイルの一括転送が接続エラーになったため、2 MiB の分割転送を使用する。結果 JSON と各 run のモデルは experiments 配下へ回収し、終了時に GPU を解放する。


## 初回実行の状態と回収方式の修正

初回の比較プロセスは終了コード0を出したが、長い Colab CLI exec 呼び出しが戻らなかった。確認時点でサーバーに専用セッションは残っておらず、最終JSONとモデルを回収できなかった。セッション終了の直接の原因・時刻は確認できていない。成功した比較結果として扱わない。

ローカルに回収できた初期モデルの基準値（PyTorch）: 正規化 Accuracy 52.7419%、Macro-F1 42.6750%。take 45.3846%、yu-ota 90.1961%、reon 91.8367%。takeは104原ラベル、残る2名は母音5ラベルなので全話者の数値を同じ課題の難易度と見なさない。共通母音のみではtake 51.7241%（29件、woもoに統合）、yu-ota 90.1961%、reon 91.8367%。

再実行先は vr-si-20261003-a100ad-r2。元の入力アーカイブから初期モデルをworktree内へ取り出し、SHA-256一致を確認した。データ・学習条件は維持する。

再実行版は学習をバックグラウンドで起動し、短いCLI接続で5分ごとに進捗と途中JSONをローカル回収する。JSONは一時ファイルからの置換で保存し、書き込み中のファイルを回収しない。CLI呼び出しと実験全体に時間制限を設ける。途中回収はexperiments/vr-si-20261003-a100ad-r2/progress/、最終回収は同ディレクトリのresults/に保存する。
