# 新規データの棚卸しと評価話者候補（2026-10-04）

対象は PR #56 マージ後の Main、コミット `753a1428d59e4e2a194aa6656ae629b8c5c9cb68`。作業ツリーを切り替えず、Gitオブジェクトから対象コミットのデータを直接検査した。学習・評価推論・既存CSVの更新は実施していない。

## 提案

新規男性話者の主ベンチマーク候補を **Val: r2 / r4、Test: r3 / r5** とする。残る r1 / r6 / r7 / r8 / r9 / r10 をTrain候補とする。これは候補案であり、学習用固定分割へはまだ適用していない。

ユーザー確認: r番号が話者の区別で、r1〜r10は全員男性。既存の名前付きID・pc IDとの人物対応は、この確認だけでは確定しない。

追加確認: 新規r音声は人間によるラベルチェック未完了。ユーザーの指定により、既存モデルで全2,384件を推論し、収集ラベルと予測が不一致の音声のみを聴取確認する。専用画面は `evaluation_results/r_label_review.html`、判定保存先は `evaluation_results/r_label_review_decisions.json`。モデル一致の音声を自動で人間確認済みにはしない。候補分割の実適用はレビューによるラベル修正を反映した後に行う。

| 区分 | 話者候補 | 新規データ件数 | 評価対象 |
| --- | --- | ---: | --- |
| Train追加 | r1, r6, r7, r8, r9, r10 | 1,552 | 学習用。既存Trainへの追加候補 |
| Val | r2, r4 | 416 | 104音節、各音節4件 |
| Test | r3, r5 | 416 | 104音節、各音節4件 |

全104音節を各2件持つr1〜r7を候補母集団とし、IDを辞書順に並べて Python `random.Random(42).shuffle` を適用した。先頭2名をVal、次の2名をTestへ割り当てた。モデルの成績や推論結果は選定に用いていない。録音数の多いr10と欠落音節のあるr8/r9をTrainに残すことで、同じ件数・網羅率のVal/Testを作る。これだけで年齢・声質・録音環境の代表性が保証されるわけではない。

Val/Testの人物ID集合が互いに交差しないこと、各416件・104ラベル・各ラベル4件であることを検証した。2名ずつなので、未知男性全体への汎化については話者数の制約がある。男女混合の最終ベンチマークを完成させるには、別の女性生声Val/Testが必要。

## Main全体の機械検査

既存DatasetBuilderと同じく、`dataset/<speaker>/<label>/*.wav` と、collectedのmetadata.csvに有効な正解ラベルがある存在ファイルを対象とした。Git管理対象のみの検査であり、ローカル未追跡音声は含めない。ファイル内訳・音声ハッシュ・形式・基本波形統計を `inventory.json` に保存した。

- 対象10,532件、26ディレクトリID。人物数ではなくID数であり、TTS 312件とpc ID 5個を含む。
- WAV読み取りエラー0、完全なゼロ信号0、絶対値32760以上のPCM16サンプルが1%を超えるファイル0。
- RMSが−45 dBFS未満のファイル35件。小音量の確認候補であり、機械的に無音や不良とは判定しない。
- 新規r1〜r10には、全体とのバイト一致・PCM一致の重複、ゼロ信号、小音量候補、上記クリッピング候補はない。
- metadataが参照するGit管理対象WAVの欠損1件: `dataset/collected/pc_699ec508/1786019024_356911.wav`。既存統合処理はファイルがない行をスキップする。
- バイト一致・PCM一致の重複はともに34組・68パス。rinry 13組、take 21組で、全組に異なるラベルが付いている。詳細は `label_conflicts.csv`。

例: `dataset/rinry/be/031.wav` と `dataset/rinry/re/036.wav`、`dataset/take/de/001.wav` と `dataset/take/ze/008.wav` は同一音声で異なるラベル。追加先がラベル修正の意図でも、対象Mainのツリーには旧パスが残っている。どちらが正解かはハッシュでは判断できないので、修正履歴または聴取で確定する。それまでは両方を学習対象から保留する。音声の削除やラベルの自動変更は行っていない。

今回の検査は音声形式・基本波形統計・完全一致重複の機械検査。発話内容の正しさ、発話切れ、雑音、近似重複、声質・録音環境の代表性は未検証。

## 既存データと評価の扱い

1. 旧固定Val/Testは過去に参照済みの回帰ベンチマークとして保持する。特にtakeは女性生声の回帰確認用に残すが、新しい盲検Testとして扱わない。元CSVとデータハッシュを維持して比較する。最新ツリーの再列挙で旧評価集合を上書きしない。
2. 既存の `script/create_speaker_independent_splits.py` は話者の固定リストを使い、r1〜r10を含まない。新規データはそのままではUnknown側に落ちるため、実適用時に明示的な人物対応表・固定分割へ反映する。
3. rinry/takeのラベル競合を解消する。既存Trainへ追加する前に、rikuto/rikutomike、ryu/mikeryu、pc IDの人物対応も確認する。評価人物の別IDがTrainに入る場合は人物単位で除外する。人物不明のpc音声は厳密な分割では保留する。
4. 生声の基準実験ではTTSをTrainに入れず、追加効果は後続の比較で確認する。過去チェックポイントの対象人物への学習履歴が分からない場合、継続学習は探索的な比較として区別する。

## 次の実施順序

1. 候補話者と既存IDの人物対応を確定し、Val/Test候補の内容・発話切れ・環境をモデル推論を使わずに確認する。両集合の収録範囲は維持する。
2. 既存のラベル競合を確認し、採用ラベルと旧パスの除外を記録する。確認できない組は全パス保留とする。
3. 固定CSVを実生成し、人物・ファイル・SHA-256/PCM重複・欠損を検査する。source_filepathによる前処理後の対応を検証し、ランダム再分割を禁止する。
4. Valの同音統合後Macro-F1を選択指標として、Wav2Vec2基準条件を学習する。Train由来のクラス重み・拡張だけを用い、Test由来の混同サンプラーを使わない。
5. 同じ分割で子音・母音補助学習を比較する。Valで設定・チェックポイントを確定してからTestを評価する。生ラベル、同音統合、話者別・話者平均の成績と、別集合のother評価を保存する。
