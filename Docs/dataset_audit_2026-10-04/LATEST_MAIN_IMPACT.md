# 最新Mainとラベルレビューへの影響

調査日: 2026-10-04。リモートMainは `60e25076f29402cc8b7f2da32da1db10ade7e271`（PR #57）。レビュー生成時と現在のローカルHEADは `753a1428d59e4e2a194aa6656ae629b8c5c9cb68`。fetchのみ行い、ローカルのチェックアウト・レビュー画面・判定JSON・音声を更新していない。

## 結論

保存済みの人間の判定をやり直す必要はない。Main更新で音声本体、ラベル定義、レビュー機能、モデル重みは変更されていない。新規r音声2,384件を旧・新の実装で前処理したところ、処理後の波形は全件で完全一致した。今回のコード更新によって、このr集合の不一致候補を再抽出する必要はないと判断する。

一方、追加された固定分割CSVは、今回の人間によるラベル修正30件を反映していない。学習前に判定をデータへ適用し、分割CSVと前処理済みデータを再生成する必要がある。Mainの分割既定値も、このチャットで提案した話者構成とは異なる。

## Mainの変更

### 発話開始位置の補正

`AudioPreprocessor` に `onset_pre_roll_seconds=0.1` と `find_speech_onset` が追加された。トリミング無効時でも、検出した発話開始の100ms前から切り出す。マイクの1秒窓の後半に発話がある場合など、先頭0.6秒の固定窓から発話が落ちるケースを改善する意図の変更。

`Wav2Vec2Recognizer` と学習データ構築の双方がこの前処理を利用するので、一般には同じモデルでも推論結果や学習入力が変わり得る。ただし今回のr音声では、切り出し位置の変更が発生しなかった。

検査方法:

- 対象: レビュー用indexの全r音声2,384件。すべて16kHz・モノラル・PCM16。
- 旧コミットと新コミットの実際の `AudioPreprocessor` クラスをASTから読み込み、PCM16をfloat32へ変換した独立の波形コピーに実行。
- 既存Wav2Vec2と同じ既定設定（トリミング無効、0.6秒、target RMS 0.12）を使用し、処理後配列を完全一致で比較。
- 変更0件、同一2,384件。比較処理自体は遅い発話開始の合成音で差が出ること、早い開始の合成音で一致することを確認。
- 既存ONNXモデルのSHA-256も前回レビュー生成時と一致。`af10787f4b6803d383558476e4a6cdbb22eb3a2e4ad4691c39816473ca825337`。

今回、最新コードで全件のモデル推論を再実行したわけではない。モデルと入力波形の同一性から、候補再生成が不要と判断した。音声品質の人間判定は、モデルの当否とは独立に有効。

### マイク録音の待機時間

`speech_settle_seconds` が0.3秒から0.45秒へ変更された。リアルタイム録音のVAD検知後の待機に使われる。保存済みWAVを後から延長・修正する変更ではなく、今回の保存済み音声・判定には影響しない。

### 固定分割の追加

`script/make_fixed_split.py` が追加された。TrainとValだけを専用の前処理ディレクトリへ出力し、Testを含めない構成。学習時は既存の `--train-csv` と `--val-csv` を明示して利用する。

追加された固定CSVの実測:

| 分割 | 件数 | 話者ID |
| --- | ---: | --- |
| Train | 7,905 | ai_female_nanami, haruyamike, r1〜r7, rikuto, rikutomike, rinry, ryu, collected |
| Val | 1,679 | yumike, mikeryu, r9, r10 |
| Test | 948 | take, yu-ota, reon, r8 |

このチャットの候補はVal r2/r4、Test r3/r5であり、Main既定値はそれらをTrainに入れる。提案は候補段階で未適用だったので、既に固定済みの分割を壊した変更ではない。ただし実際の学習を始める前に、どちらを採用するか明示する必要がある。

既定Valにはotherがない。r8にはdoがなく、takeを含む旧評価のラベル競合も未解消。TTSもTrainに含まれる。これらは以前に提案した「生声での基準比較」と異なる条件なので、結果を混同しない。

## 学習へ進む順序

1. 現在の画面で残る不一致候補の確認を続ける。Main更新だけを理由に確認済み音声をやり直さない。
2. 最終判定JSONを保存・バックアップし、ラベル修正・other・削除候補・保留の取り扱いを確認する。
3. 修正をデータに反映したうえで統合indexを再生成する。既存rinry/takeの34組のラベル競合も、解消または対象保留を行う。
4. 評価話者を明示し、固定分割CSVと前処理済みデータを再生成する。元音声の移動後は旧レビュー画面のパスが古くなるため、音声移動とレビュー再生成は一緒に行う。
5. 固定Train/Valを指定して学習する。実人物の別IDやpc IDの対応が未確認である点も、話者独立評価の前に確認する。

詳細な機械集計は `latest_main_impact.json`、前処理比較は `latest_preprocessing_impact.json` に保存した。
