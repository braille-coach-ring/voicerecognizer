# 音声モデルの学習・評価方針

2026-10-04にユーザーと確定した継続方針。目的は未知の人物・声質・録音条件への汎用性。
汎用性の判断を全体の録音件数加重Accuracyだけに依存させない。
以下の主指標は、本プロジェクトの目的に合わせてBalanced Accuracyを話者間でも均等化した設計であり、唯一の普遍的な指標という意味ではない。

## 人物情報と混合群の正しい扱い

- **Rinryおよびcollectedは多様な人物・マイク条件を含む混合プール。**
  - 未知話者2名（r2/r4）のみの過適合を防止し、全体の認識性能・基礎体力を客観的に測るため、ユーザー指示（2026-10-04）に基づき Train/Val/Test に層化配分（80% / 10% / 10%）して「全体汎用指標」の母集団として活用する。
- **個人IDが確定している話者（r1〜r10, take, yumike, mikeryu 等）は厳密な話者分離を100%維持。**
  - r1/r6/r7/r8/r9/r10 は Train、r2/r4 は Val、r3/r5 は Test。
  - take/reon/yu-ota は Test、yumike/mikeryu は Val。
  - この厳密未知話者群は分割間で絶対に重複させない。
- 不明は不明として集計する。性別や人物数を声質・名前・ファイル名だけから推測しない。
- 女性生声takeとTTS Nanamiは別集計。Rinry全体を女性精度の分母にしない。
- 根拠を`Docs/speaker_identity_facts.json`に記録する。

## 分割設計

正規分割: `data_splits/speaker_mixed_balanced_20261004/{train,val,test}.csv`。
実行入口の既定値は`DEFAULT_SPEAKER_SPLIT_DIR`で統一する。

| 区分 | 厳密分離話者 | 混合母集団（多人数・環境プール） |
| --- | --- | --- |
| Train (約7,173件) | rikutomike, haruyamike, rikuto, ryu, r1/r6/r7/r8/r9/r10, tts_nanami | rinry (80%), collected (80%) |
| Val (約1,916件) | yumike, mikeryu, r2, r4 | rinry (10%), collected (10%) |
| Test (約1,478件) | take, reon, yu-ota, r3, r5 | rinry (10%), collected (10%) |

- 既存所属を維持し、新規録音のみを追加する。全体のランダム再分割を行わない。
- 新規人物は、その人物の全録音・別名・派生音声を同じ集合へ置く。データ拡張は分割後にTrainへだけ適用する。
- 元録音、切り出し、増幅、音量変換などの派生は別集合へ分離しない。
- 人物ID、元録音ID、ファイルパス、SHA-256/PCM一致、ラベル競合、欠損を検査し、異なる検査の意味を明記する。
- 環境音は話者ではなくセッション/場所/端末条件で保留する。同じ収録セッションの10件保留を未知環境全体の評価と呼ばない。
- 未確認ラベルを確認済みと扱わない。rの116件はユーザー承認により収集ラベルで採用した記録を保持する。
- 旧ランダムCSV・旧ランキングは履歴用途。最新の正式精度・独立Testとして再利用しない。

同一人物に由来するサンプルは独立ではなく、人物グループを集合間で分けることが基本。
[scikit-learnのgrouped cross-validation](https://scikit-learn.org/stable/modules/cross_validation.html#group-k-fold)がこの分離の根拠。

## 評価課題をそろえる

1. 広い音節範囲の生声課題: Valではyumike/r2/r4、Testではtake/r3/r5が現状の候補群。
2. 5母音課題: reon/yu-ota等。全音節課題へ混ぜて1つの主指標にしない。
3. 環境音の拒否課題: otherの認識と音節への誤受理。人間の話者平均から除外する。
4. TTS: 補助学習・補助評価。生声や未知女性の評価の代用にしない。

課題ごとに評価対象の人物Sと音節集合Cを、予測結果を見る前に固定する。
主指標では各人物に同じCの正解音声があることを検証する。欠落音節を0点で埋めない。
音節数・欠落・各音節の件数を併記し、固定した共通集合上の評価と各話者の全保有音節評価を区別する。
同音統合後の現在のtake/r3/r5共通発声音節は100種類。これは集合の正解ラベルからの範囲確認であり、誤りを消すための後付け音節選択ではない。
今後は新しいVal/Testの課題集合を同じ基準で事前に確定する。

## 主指標と副指標

主指標は **話者均等Balanced Accuracy**。
各話者について音節ごとのRecallを平均し、その値を話者間でも等しい重みで平均する。

`BA_s = mean_{c in C}(正解数[s,c] / 正解音声数[s,c])`

`主スコア = mean_{s in S}(BA_s)`

全音節・同じ課題の各人物を等しく扱うため、録音数が多い話者や音節が主スコアを支配しない。
Balanced Accuracyはクラス別Recallの平均という標準定義に基づく。
[balanced_accuracy_score公式定義](https://scikit-learn.org/stable/modules/generated/sklearn.metrics.balanced_accuracy_score.html)。

| 指標 | 役割 | 必ず併記するもの |
| --- | --- | --- |
| 話者均等Balanced Accuracy | Valでのモデル選択と同一課題での汎用性比較の主指標 | 人物・課題・音節集合・人数・件数 |
| 話者別BA/Accuracy/Macro-F1 | 得意/不得意・回帰低下の把握 | 最低話者、範囲、既存モデルとの差 |
| 話者均等Macro-F1 | 音節の見逃しと誤予測の両方の補助評価 | 評価対象音節とzero-supportの扱い |
| 件数加重Accuracy/Macro-F1 | 現在の評価集合全体での参考値 | 話者別件数・寄与率。主指標と呼ばない |
| 確認済み性別別・条件別の話者平均 | 性別/環境による偏りの把握 | 人数・不明人数・音節範囲。女性1名で女性全体を保証しない |
| 5母音課題の話者均等BA | 同一課題の既存男性回帰確認 | 広い音節課題と別スコア |
| other再現率/環境音誤受理率/発話誤拒否率 | 雑音や発話を取り違える実用上の失敗の把握 | 音声種別、収録条件、分母 |

Macro-F1は各クラスのF1を均等平均するが、単に全話者をまとめたMacro-F1は話者を均等に扱わない。
[f1_scoreの平均方法](https://scikit-learn.org/stable/modules/generated/sklearn.metrics.f1_score.html)。

other再現率 = 正解otherをotherと予測した数 / 正解other数。
環境音誤受理率 = 環境音を発声音節として予測した数 / 評価環境音数。
発話誤拒否率 = 正解発声音節をotherと予測した数 / 正解発話数。
発話を別音節に誤分類したものは音節分類の誤りとして保持する。
後付けで誤予測を除外しない。閾値がある場合はValだけで選ぶ。

厳密ラベルと同音統合後の両方を保存する。
同音統合は固定のdi→ji、du→zu、wo→o。音声として同じ音の識別を主目的とする本プロジェクトでは同音統合後を主スコアとし、文字ラベルの厳密正解率も併記する。
生の予測は上書きしない。真値・予測の双方へ同じ写像を適用する。

前に報告した「5話者均等Accuracy 68.49%→66.03%」は、5母音のみの2話者と広い音節範囲の3話者を混ぜた参考集計。
これを新しい主指標と呼ばない。件数加重58.80%も単独で汎用性の改善と結論しない。

## 学習とモデル選択

- 「全件学習」の既定は、全Trainを毎エポック最低1回使う方式。基本は全件シャッフル、重複なし。
- 必要な追加抽選/オーバーサンプリングは全件通過とは別枠にして、件数と重みを記録する。
- 音節・人物・環境の配分を分けて設計する。性別不明を女性へ割り当てない。
- 音節は現在65〜123件と比較的均等。抽選と損失で二重に補正する必要性をValで検証する。
- 人物補正は確認済み人物IDに対して行う。Rinryを1人として均等化せず、未分離の混合群として扱い、個々の人物均衡は未実現と明示する。
- ファイル件数・人物数・収集群数・抽選期待比率・実際の使用回数を区別する。
- 全件利用を主張する場合はepochごとの実使用ID・未使用数を記録して検証する。
- Augmentation、クラス重み、学習する前処理統計、サンプラーはTrainだけから作る。
- 固定の波形変換はVal/Testにも同じものを適用するが、評価音声から学習統計を推定しない。
- モデル・早期停止・閾値・重み・許容する群別低下はValで事前に決める。Testの混同や点数で選び直さない。
- Valに女性生声の評価人物が必要。現在のValに確認済み女性生声の評価群がないため、女性汎化をモデル選択で検証できない。
- takeをTestからVal/Trainへ移して帳尻を合わせない。別の女性生声人物の追加が必要。
- 重要群や最低話者の低下を必ず説明し、平均だけで自動採用しない。群別許容差はValで事前固定する。

Testをモデル選択や学習する前処理へ使わないことは、標準の漏洩防止原則に従う。
[scikit-learn Common pitfalls](https://scikit-learn.org/stable/common_pitfalls.html#data-leakage)。

## 信頼性・再現性・報告の定型

- 人物数、セッション数、件数、音節範囲、欠落、性別情報の根拠を示す。
- 人物汎化の不確実性は人物単位で扱う。同じ人の多数録音を多数の独立人物として扱わない。
- 信頼区間は同一人物を保持するpaired cluster bootstrap等で求める。人物数が少ない場合は限界を明示し、女性1名から女性全体の区間を作らない。
- 開発比較は可能なら複数seedやTrain/Val内の人物Group CVで安定性を確認する。固定TestをCVへ混ぜない。
- 比較する2モデルは同じCSV・ラベル・前処理・backend・音節集合で測る。
- CSV、音声、コード、checkpointのハッシュ、seed、抽選方法、学習率、拡張、選択epoch、停止理由を保存する。
- ONNX/量子化等の変更後は実運用artifactで再評価し、PyTorch結果をそのまま転記しない。
- 反復参照済みの現在のTestは回帰ベンチマーク。新しい盲検最終評価を主張しない。

報告順: 分割と検証範囲 → 主指標 → 話者/性別/条件別と最低値 → 5母音回帰 → otherの失敗率 → 参考の全体値 → 不確実性/来歴 → 保存先。
Rinryの訂正後、現時点でTrainの生声男女比は算出不能。録音件数の多さを人物の多様性と同一視しない。

## 現在の実装との差

### スピーカーフォンを優先する運用方針（2026-10-04）

実運用デバイスがスピーカーフォンへ変更されたため、未知話者のスピーカーフォン性能を主な採用判断にする。
他デバイスの性能も独立して報告し、全体平均へ埋め込まない。学習の重みと評価の優先順位を区別する。
詳細は `Docs/SPEAKERPHONE_WEIGHTING_PLAN_2026-10-04.md` を参照。

- 既存の人物分割を維持する。端末を理由に同じ人物をTrain/Val/Testへ分散させない。
- 端末別に、同一課題の話者均等Balanced Accuracyを比較する。女性、既存ベンチマーク、5母音課題、otherの失敗率も継続報告する。
- デバイス損失係数の既定は1倍。全Train通過を保つ対照実験でのみ1/2/4倍等を比較し、改善が確認されるまで重み増加を既定へ採用しない。
- 分類層だけのローカル予備実験は実施済み。2倍の主指標の上積みは平均0pt、4倍は平均+0.21ptでseed間で一貫せず、既存Valには低下があった。詳細は `Docs/LOCAL_SPEAKERPHONE_PROBE_2026-10-04.md`。これはencoderを更新する学習での効果を否定する結果ではない。
- ユーザーは比較実験に時間をかけずにスピーカーフォン性能を向上させたい。次の作業は重み/更新層/seedの比較探索ではなく、本学習1回に絞る。既存checkpointからclassifierとencoderの一部を小さい学習率で更新し、既存の軽い音声拡張を利用する。全Trainを毎epoch通し、デバイス係数は1倍を維持する。更新層と重みは別の要因であり、この1回で得た改善を重み増加の効果とは説明しない。
- checkpointの選択・早期停止はr2/r4の同音統合済み話者均等BAを主指標にする。既存Valのyumike/mikeryuとotherの失敗率も監視する。選択完了後、take/r3/r5のスピーカーフォンTest、女性take、既存5母音Test、環境音を1回の回帰評価で報告する。比較実験の省略は評価の省略を意味しない。
- スピーカーフォンのみの学習は、全件学習とは別の明示的な比較実験として扱う。通常の全件利用を黙って変更しない。
- Valで許容する他デバイスの低下と必要な改善幅を事前に決める。Testで重みや採用基準を調整しない。
- 旧speakerphone CSV合計1,035件は現行正式分割ですべてTrain。旧speakerphone Testを復活させても独立評価にならない。
- ユーザー確認でtake・r話者・最近のRinryはスピーカーフォン収録。現行Valのr2/r4、Testのtake/r3/r5をスピーカーフォン評価候補にする。最近のRinryのファイル範囲と他群のデバイスは未確定。旧CSVだけで評価不可能とした調査時点の判断は、この確認で更新された。

直近モデルは旧実装の「全Valをまとめた同音統合Macro-F1」で選択され、重複ありWeightedRandomSamplerで学習された。
人物対応も未確定である。ローカル分類層予備実験には全件通過とr2/r4主指標を実装したが、本格trainerへの新しい主指標・全件通過・人物台帳の評価連携はまだ完了していない。
次の学習・ランキング実行前にこの方針へ実装を合わせ、意味のある小さなチェックで検証する。
今回の文書作成を、モデルが新しい評価方式で選択済みという説明に使わない。

### 更新範囲についての文献と解釈

固定特徴上の分類層更新では録音デバイスに合わせて特徴抽出そのものを変更できない。
wav2vec 2.0の原論文は、事前学習した音声表現を教師あり学習でfine-tuneする有効性を示す。ただし本データでの端末重みの改善量は示さない。
[wav2vec 2.0](https://arxiv.org/abs/2006.11477)。
更新層を増やすと端末への適応余地が増える一方、他条件での性能低下も起こり得る。
更新範囲を選ぶ有効性と、full fine-tuningによる特徴の変形・分布外性能低下は主に画像データで報告されている。
音声への直接的な改善保証ではなく、部分更新を候補として汎用性も評価する根拠として扱う。
[Surgical Fine-Tuning](https://arxiv.org/abs/2210.11466)、[Feature distortion](https://arxiv.org/abs/2202.10054)。
したがって「今回は分類層だけだったことが唯一の原因」「下層を更新すれば必ず改善」は断定しない。
